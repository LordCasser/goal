# Goal 数据与隐私边界

本文档对应 `v0.1.0`，描述当前实现的本地存储和 AI 请求边界。Goal 不提供账户体系，也不把计划数据同步到 Goal 自己的服务器。

## 本地保存什么

应用数据由 Tauri 的本地 app data 目录管理，主要包括：

- `planner.db`：周期、任务、日历、专注块、提醒、设置、Coach 会话和待确认预览等本地业务数据。
- `providers.json`：供应商名称、Base URL、API 格式、模型元数据、额外请求头和当前选择等非密钥配置。
- `logs/`：按设置级别保存的本地日志。日志模块会对已登记的密钥做遮蔽。
- `~/.goal/persona.md` 和 `~/.goal/skills/`：用户自定义的回答风格和工作流文件。

这些文件不构成云端账户。备份导出的是本地数据库副本，可能包含计划、会话和预览内容；API Key 不在数据库副本里，因为它存放在操作系统凭据存储中。

## API Key 放在哪里

供应商的 API Key 只通过系统凭据存储保存：

| 平台 | 存储位置 |
| --- | --- |
| macOS | Keychain |
| Windows | Credential Manager |
| Linux | Secret Service |

应用不会把 Key 写入 `providers.json`、SQLite 数据库或日志，也不会在普通设置页面回显完整 Key。删除供应商时会同时清理对应的凭据项。

`providers.json` 中的额外请求头被当作非敏感配置保存。不要把 Token、密码或其他秘密放进额外请求头；需要认证时使用专门的 API Key 字段。

## 什么时候会联网

没有配置 AI 或没有触发 AI 功能时，应用不会因为打开、编辑计划或查看日历而上传计划数据。当前实现没有遥测、广告、账号登录、云同步或自动更新网络通道。

网络请求只发生在用户配置并调用供应商的功能中，例如：

- 供应商连接测试；
- Coach 对话和 Plan with AI；
- 目标澄清、优先级、复盘、时段分析；
- Issues 中主动点击的 AI 检查。

本地模型服务也按普通供应商处理，例如 `http://localhost:...`；请求是否离开本机取决于你填写的 Base URL。

## AI 请求会带什么

一次 Coach 或分析请求可能包含：

- 你当前的提示和该周期的历史对话；
- 当前周期的类型、日期、父 / 子周期关系和可见任务；
- 任务标题、完成状态、父目标关系、需要澄清或拆解的标记；
- 当前日期时间，以及用于解释任务关系的工作 mix 统计；
- 如果正在处理某个目标，目标拆解快照和相关任务信息；
- `~/.goal/persona.md` 和当前技能的 `SKILL.md` 内容；
- 模型要求的工具描述，以及本轮工具返回给模型的读取结果。

API Key 会作为供应商协议的认证信息发送给你选择的 Base URL，但不会作为普通对话内容放进上下文。Goal 不会把 Key 输出给模型、日志或错误消息。

供应商可能按照自己的隐私政策记录请求、提示词、响应和账号用量。Goal 无法控制供应商的保留期限、人工审查、训练政策或跨境处理；使用云端供应商前应阅读其条款。需要把数据留在本机时，使用你信任的本地模型服务并确认 Base URL。

## 会话过期

Coach 会话按计划周期隔离，并保存在本地数据库。默认没有新对话 15 分钟后，应用会清理该周期的会话消息、活动技能和上次错误；可以在 AI 设置中改为 1–1440 分钟。读取会话不会延长过期时间，正在执行的回合不会被强制中断。

过期只清理本地会话上下文，不会撤回已经发给供应商的数据。供应商侧的副本只能按供应商自己的策略处理。

## Coach 写入边界

模型可以提出创建、编辑、删除、移动、归属、颜色、周期、专注块、提醒或设置等操作，但应用把这些操作保存为待确认预览。用户确认之前，本地业务数据不应被这些提案直接修改；用户放弃则不会执行。读取类工具可以在生成过程中读取当前本地上下文，结果也可能被继续发送给同一供应商。

因此，使用 Coach 时要把“模型看到哪些本地数据”和“模型建议什么”分开理解：模型可以看到被注入的上下文，但只有应用的确认流程可以完成受保护的本地写入。

## 自定义文件的边界

`persona.md` 和 `SKILL.md` 是用户可编辑的提示内容。它们会被读取并注入 AI 请求，所以其中的文字可能发送给当前供应商。不要在这些文件里保存 API Key、密码、个人身份号码、Cookie 或其他秘密。

## macOS 安装提示

当前 macOS 包没有 Developer ID 和 Apple notarization。Gatekeeper 可能提示开发者无法验证；确认下载来源和校验值后，按 [Apple 的 Open Anyway 说明](https://support.apple.com/en-gb/102445) 在“系统设置 → 隐私与安全性”中允许这一份应用。不要通过全局关闭 Gatekeeper 来绕过系统保护。

构建使用固定的自签名身份，但没有公证。旧 ad hoc 包升级到固定签名包时，系统可能再次询问钥匙串访问；之后同签名更新会继续使用同一应用身份。这个签名策略不等同于 Apple 对应用进行安全审查。
