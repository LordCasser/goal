# Goal 公开设计快照

这份文档记录 Goal 当前产品界面的自有原则与已实现方向，服务于后续界面实现、评审和跨平台验收。它描述用户能感知到的结构和行为，不承担后端数据契约或平台构建说明。

## 设计目标

Goal 是一张连续的工作台：长期结果形成方向，本周计划形成承诺，今天的行动形成下一步，专注块承接执行。用户在任何一个层级都应能回答三个问题：我正在看哪段时间、这项行动服务于什么、下一步可以做什么。

界面遵循以下原则：

- 内容优先。任务标题可以直接编辑，主要空间用于阅读、安排和执行。
- 关系按需显露。归属使用色标和名称保持可见，完整关系在用户查看时展开，不让连线遮住正文。
- 控制权清楚。创建显示日期后果，删除显示影响，AI 改动先预览并由用户确认。
- 允许计划不完整。事务可以暂时未关联目标，Later 用于快速收纳，不阻塞记录和执行。
- 状态可读。完成、选中、提议、失败和当前操作使用不同的局部表达，不依赖低透明度或单一颜色。
- 键盘可达。主要动作有稳定焦点、Escape 关闭当前浮层、关闭后焦点回到触发入口，并尊重减少动态效果设置。

## 主题与视觉语言

应用提供白底和灰底两种浅色主题。两种主题共用布局、字体和交互，仅改变画布与内容面的层次：白底主题使用连续白色表面；灰底主题使用浅灰画布承托白色内容面。主题选择持久化，启动时先恢复已选主题。

界面消费语义化颜色：画布、内容、辅助表面、hover、正文、次要文字、提示文字、边界、焦点、暖色强调、危险和待确认。正文保持实色和足够对比度；暖色用于运行状态，危险色只用于破坏性动作，焦点蓝用于键盘和当前导航。字体优先使用 IBM Plex Sans，中文使用系统回退字体，计时使用稳定宽度的数字。

## 工作台与任务层级

Workspace 将长期、周、日和执行串成一条计划路径。时间导航选择当前周期，计划面显示标题、日期、任务和状态。周、日导航采用日期选择器式鼓轮：周和日期跨年按真实时间连续排列，只有中心跨过当前行窗口边界时才更新有界窗口，永不循环或重复同一日期。鼓轮行、视口和空态容器保持固定高度，当前周和今天身份以内联标签显示在真实行中；每个身份行按逻辑日期 index 计算自然位置，正常位置可见时跟随内容，离开视口时同一行按滚动方向夹到视口顶部或底部，不插入重复列表行或底部返回控件。无计划的周和日期可以浏览并显示空态，只有明确创建动作才写入计划。

指针悬停在周或日鼓轮上时，该鼓轮独占纵向滚轮并抑制工作台横向移动，不需要点击或取得焦点。滚轮使用阻尼平滑吸附，中心候选需在滚轮静止至少 500ms 且运动结束后才提交，中间候选不打开面板。点击行、Enter、Space 可直接选择；方向键、Page、Home（本周/今天）沿用相同的 500ms quiet + settled 条件。点击当前周/今天行会平滑居中并打开对应计划或空态。选择周后日鼓轮平滑定位到已保存的周起始日或周起始设置；选择日期后选中日期及所属周，并平滑对齐周鼓轮。程序定位不产生新的用户提交或反馈循环。减少动态效果时只将视觉移动改为即时，滚轮和键盘仍遵循相同防抖。计划卡和专注块的实际内容区仍需鼠标主键点击后才纵向滚动，点击标题或区外恢复工作台横向浏览。

鼓轮滚动帧只移动已经渲染的有界日期行，不在每帧重建 React 行或重新格式化日期；只有中心跨过当前行窗口边界时才更新有界行集合，复用已有格式化标签，仅为新增行格式化，不引入额外批量缓冲层，固定视口、固定高度和同一 current 行的夹边/回中保持不变。停稳后的周/日面板切换保持原位内容：目标面板的任务和专注块数据全部就绪前，旧内容保持可见且不可编辑；就绪后内容约 160ms ease-in 淡出至 opacity 0，卡片边框和背景保持不透明，目标内容原位约 260ms 缓启动缓停止淡入至 opacity 1。整卡不使用 translate 或 scale，卡片自然高度只在切换期间约 260ms 平缓插值并遵守可用高度上限，不短暂坍塌。快速连续导航从当前显示状态接续，只保留最新目标和单一 live 内容树；减少动态效果时数据就绪后立即替换。


计划卡按任务量自然增长，最小约 360px，并受工作台当前可用高度限制，避免窗口出现纵向溢出，也不始终拉伸到整屏。任务很多时，卡片头部和底部工作量摘要固定，只有中部任务行在卡片内部滚动；专注块侧卡使用同样的有界高度和独立滚动区，内容区仍需鼠标主键点击后才激活纵向滚轮。

同周期步骤是任务结构，跨周期关系是目标归属，二者使用不同的视觉和操作入口。日历中悬停目标只临时预览；点击任务或目标后，沿真实父链至长期目标、向下沿所选事项的子项持续高亮，再次点击、点击空白或按 Esc 取消。日、周、长期目标使用一致的归属色反馈；查看关系不会修改归属。任务状态可以叠加：完成不取消关系，提议不覆盖草稿，保存失败保留输入并提供恢复路径。

计划编辑器的空输入行始终显示在所有可见事项之后。Later 恢复项排在空输入行之前；新增、复制等其他路径维持原有事项顺序。空输入行继续使用现有行内输入方式，事项标题继续在原行内编辑。

双击非空事项打开详情弹窗，查看或改写该事项自己的纯文本备注；单击标题仍用于行内编辑。详情注明事项所属周期与直接上级目标，已结束周期中的事项只读。日事项详情还按日期列出当前同一事务段落中的记录及各自备注。事务按顶层日事项的标题（忽略首尾空白）和直接上级目标身份归组；没有上级目标的事项仅与同样未关联的事项匹配。专注块不决定事务身份。当天同组记录任一完成即在该日末结束当前段落，之后再出现时另起一段；历时按首末记录日闭区间计算，同时显示实际有记录的天数，空白日期不计入记录天数。更名、完成状态或直接链接变化后按当前关系重新归组。

非空且可编辑的任务行保留小型拖动把手，默认隐藏，悬停行或键盘聚焦时显示，单项计划也遵循这一交互；把手仅用于同一计划列表内排序，不增加独立的调整顺序按钮；跨计划拖动不改变顺序或目标关联。目标关联和专注块排期使用可见菜单或表单，不依赖拖放。日期卡片改期与批量删除使用自有右键菜单，不在卡片顶部增加按钮；菜单键和 Shift+F10 提供同样入口。文本编辑区域的右键菜单保留剪切、复制、粘贴和全选，并保持当前文本选区。

长期周期的检查安排使用日期旁的轻量文字入口，直接显示检查节奏；详细日期在浮层中按需查看，避免为辅助信息增加常驻通栏。创建弹窗用紧凑的圆点单选行选择检查方式，不加通栏底色；间隔按“每隔 + 短数字输入 + 单位菜单”自然排列，控件不拉伸填满空白。指定一次的日期同样使用紧凑行。

工作台默认滚轮横向浏览；计划卡和专注块内容区由鼠标主键点击明确切换到纵向，点击标题或区外即解除。对应内容体激活时，现有标题预留位置只显示 14px 中性的不可交互上下箭头图标；不显示可见文字，但辅助技术可读取当前语言的滚动标签，原生 tooltip 提供说明。未激活时隐藏提示但保留空间，不增加背景、胶囊或新行，也不产生布局位移。时间导航遵循悬停独占纵向滚轮的鼓轮规则，不使用点击焦点激活。

任务和周期的破坏性操作使用明确的确认说明。Coach 提出的新增、修改和删除在原位置显示预览，确认与拒绝集中在 Coach 内完成；预览期间受影响的内容锁定，确认或拒绝后恢复正常编辑。 规划工作区中的任务、目标、稍后任务和专注块只有在删除成功且对应查询结果真正移除后才原位退场：内容约 160ms 淡出，高度或占位约 260ms 收拢，分段重叠并让后续行连续让位，不弹跳或大幅位移。退场内容不可编辑或聚焦，并设置 inert 与 aria-hidden；取消或失败保持原内容，递归删除同批退场，空态等退场完成后再出现。快速独立删除不影响新加入或恢复的同 ID 条目，减少动态效果时真实移除后立即消失。整张计划删除沿用 PlanTransition 在原位切换到下一个计划或空态，包括长期周期；删除 token、确认流程和数据库契约保持不变，这套约束只适用于规划工作区。

## 中文术语

中文界面统一使用“稍后”（Later）、“助理”（Coach）、“用 AI 规划”（Plan with AI）和“专注块”（Focus block）。翻译只作用于内置界面文案，任务标题、历史对话和用户指令文件保留原文。

## Calendar

Calendar 与 Workspace 读取同一批任务，通过月、周、日视图观察日期分布。月视图适合概览：日期与紧凑数字任务完成比同排，完整含义在 tooltip 与辅助标签中提供；底部以时钟图标和完成比呈现一次专注进度，保持单行，完整含义由 tooltip 和辅助标签提供。仅有专注块时省略无意义的 0/0 任务摘要。右键日期卡片可调整日计划日期、删除整份日计划、删除当日专注块或清除排期；三者分别确认并明确保留范围。改期使用弹窗内与页面同风格的月历，支持键盘选择，不使用系统原生小弹层。周视图保持日期列的可读宽度，日视图把当天计划与 Schedule 并列展示。切换和刷新保留日期、草稿与滚动上下文，首次进入只定位一次，不在用户滚动时抢回位置。

Schedule 展示当天专注块、预算和时间轴。专注块按真实开始时间与持续时间绘制，重叠块分列显示。已排期块和待排区都可通过时间编辑入口设置开始时间、持续时间或移回未安排区；开始时间精确到分钟，不依赖拖放或强制 15 分钟步长。短块保持真实几何高度，信息使用紧凑标签或浮层表达。取消或保存失败都会保留原计划和输入草稿。

## Coach

Coach 是右侧上下文面板，包含当前周期说明、可滚动消息区、工具过程摘要和固定输入区。用户消息、助手回复、候选回答和错误拥有稳定层级；工具调用默认折叠为摘要，需要时再展开。用户主动向上阅读时不被新消息强行拉回，发送或回到最新入口会恢复跟随。

Coach 的计划建议是提议，不是已保存事实。每张确认卡说明对象、具体变化和作用范围；执行成功后显示真实回执，失败保留提议与输入。关闭面板、切换周期或重启不会隐式确认提议。模型配置和上下文保留时间在设置中管理，密钥只在专用配置流程中处理。

## 设置

设置使用单层宽面板和左侧分类导航，右侧内容独立滚动。通用设置提供语言、主题、周起始日、显式创建新周／日计划后是否导入上一周期未完成事项，以及是否在“稍后”按钮显示事项数量；自动导入默认关闭，数量提示默认开启。AI 设置管理供应商、模型、连接测试和计划区入口；提醒设置管理通知与免打扰；诊断设置提供日志等级和可分享的运行信息。

语言、外观与周起始日可即时保存，供应商配置显式保存并区分本地状态与第三方发送。错误保留草稿，取消不写入；所有浮层都提供关闭按钮、Escape 路径和触发点焦点恢复。

## 三平台窗口壳

应用内窗口栏与当前主题画布连续，只保留一层顶部工具区。macOS 保留原生红绿灯并预留安全区；Windows 使用右侧最小化、最大化和关闭控制；Linux 遵循桌面环境的原生装饰。三个平台共享 Later、Workspace/Calendar、Coach、状态和设置的位置、字体和控件密度。

只有明确的空白区域负责拖动窗口，按钮、输入框和菜单拥有独立命中区。Windows 控件在窄窗口下保留可访问名称和键盘路径；原生适配不可用时，窗口恢复系统装饰。窗口外壳不重复显示品牌标题，不改变计划内容的滚动和编辑语义。

## 验收重点

评审应覆盖双主题切换、长标题和长列表、纯键盘操作、减少动态效果、面板组合、双击事项详情、事务历时与逐条备注、任务归属查看、提议确认、日历滚动坐标、同一计划列表内拖动排序、跨计划拖动限制、日期／排期表单、右键菜单和剪贴板，以及三平台窗口按钮、标题栏拖动、失焦和全屏状态。任何异步失败都应留下可理解的状态和可恢复的输入；成功提示应说明实际对象与动作。
