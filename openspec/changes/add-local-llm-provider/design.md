## Context

`openspec/specs/ai-access/spec.md` 定义了供应商选择与授权闸门，但只有托管与 OpenRouter 两条路径。本变更在不改变 agent 上层行为的前提下增加本地供应商。

关键约束来自既有规范与拆解结论：

- agent 的写操作全部经过提议机制（`agent-proposals`），因此供应商只需要能返回**结构化的工具调用**，不需要自己会改数据。
- 上游原实现用 `LLMProvider` trait 隔离供应商差异，我们沿用这一边界。
- 既有规范要求「支持自有凭据后的上层 agent 行为保持一致」，本地供应商同样适用。

## Goals / Non-Goals

**Goals:**

- 用一个客户端覆盖主流本地运行时，避免为每个运行时写适配器
- 本地供应商下 agent 的可见行为与托管供应商一致（除流式与延迟差异）
- 不支持的模型能力要显式暴露，不静默降级

**Non-Goals:**

- 不在应用内管理模型下载、量化或运行时生命周期
- 不做模型自动路由（在托管与本地之间按任务切换）
- 不为语音提供本地转写
- 不支持非 OpenAI 兼容的专有本地协议

## Decisions

### D1：只实现 OpenAI 兼容协议

Ollama、LM Studio、llama.cpp server、vLLM 都暴露 `/v1/chat/completions` 与 `/v1/models`。写四个适配器不如写一个正确的客户端。

代价：依赖各家对 OpenAI 协议的实现完整度。缓解：能力探测阶段实际发一次 tool-calling 请求，不信任 `/v1/models` 里的声明。

### D2：工具调用是能力要求，不是可选项

agent 的价值在于能提议改动。运行时不支持工具调用时，两种处理方式：

- 让模型输出 JSON 再由应用解析 —— 脆弱、且会把解析错误伪装成模型错误
- 明确降级为「对话模式」：agent 仍可讨论、澄清、提问，但不能提议写入

选后者。降级状态必须在界面上可见（侧栏显示当前供应商不支持改动），否则用户会以为 agent 坏了。

### D3：流式输出 + 显式超时

托管供应商可忽略这两个问题，本地模型不行：首 token 可能等十几秒。因此 `model_text` 逐块推送到前端；工具调用在流结束后统一解析，避免半截 JSON。

超时分层：连接超时短（用于探测运行时是否在跑），生成超时长（可配置，默认 120s，本地大模型可能更长）。

### D4：本地供应商不受授权闸门约束

托管 token 的作用是控制厂商成本，本地推理不产生厂商成本。因此试用结束后：

- 托管路径按既有规范停用
- OpenRouter 路径需要用户凭据
- **本地路径始终可用**

这一条修改了 `ai-access` 中「试用结束后的降级行为」的现有要求。

### D5：端点与模型选择的存储

存进既有设置表：`local_base_url`、`local_model`、`local_supports_tools`、`local_timeout_ms`。不新增表。凭据类数据（本变更不涉及）仍走钥匙串。

`local_supports_tools` 由探测结果写入并缓存，切换模型时失效。

## Risks / Trade-offs

| 风险 | 影响 | 处理 |
| --- | --- | --- |
| 小模型工具调用不可靠，产出错误的参数 | 用户看到荒谬的提议 | 提议机制本身就是护栏：所有改动都要人工 Keep；另在提示中要求模型带 rationale，界面展示 |
| 上下文窗口远小于托管模型 | 长周期上下文被截断，agent 表现变差 | 上下文注入按重要性排序并可裁剪；超出时优先保留当前周期与当前任务，丢弃历史复盘与远端周期 |
| 端点探测误报（端口被其他服务占用） | 选到非模型服务 | 探测时校验响应结构是否像 OpenAI 兼容的模型列表，并做一次最小对话请求 |
| 本地推理占用大量内存 | 用户机器变卡 | 不管理运行时生命周期；在设置页提示资源占用属于运行时，应用不做干预 |
| 流式实现引入前后端并发写入 | 消息落库顺序错乱 | 流式只推送到前端做临时展示，回合结束后一次性按序落库 |
