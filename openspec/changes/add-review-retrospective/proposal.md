## Why

基线里有一个明显断口：`cycles` 会记录 `focused_time`、会进入 `finished` 状态，创建长周期时的时间线也明确承诺了 "Review results" —— 但**没有任何复盘界面**。周期到点就静默翻篇：用户看不到「这三个月我到底做成了什么」，也没人处理那些没做完的东西。

对以「把长期目标落到今天」为核心的产品来说，这是留存上的关键缺口：没有反馈回路，第四个周期就没有理由再开。

## What Changes

- **结构化复盘**：周期进入尾声或结束后的任意时刻，提供复盘入口。复盘分两步——先看事实（完成情况、专注时长、层级链接覆盖率），再看判断（几条固定问题 + 自由记录）。
- **复盘结果持久化**：新增 `cycle_reviews`，记录事实快照与用户回答。事实快照在提交时固定，之后周期数据变动不改写历史复盘。
- **复盘驱动下一周期**：复盘结论作为下一周期规划会话的初始上下文；未完成项在复盘中逐条决定去向（带入下一周期 / 退回 Do Later / 放弃）。
- **`review` agent 技能**：复盘由 agent 引导（第五个技能），沿用既有的「一次一个焦点问题 + 候选回答」语法。
- **跨周期汇总**：一个汇总视图展示专注时长与完成率的趋势，并能把任意周期的复盘导出为 Markdown。

## Capabilities

### New Capabilities

- `review-retrospective`: 周期复盘的事实采集、结构化提问、结果持久化、未完成项去向决策，以及跨周期汇总与导出。

### Modified Capabilities

- `agent-conversation`: `ActiveAgentSkill` 从四个技能扩展为五个，新增 `review`，并定义它如何被激活。
- `planner-workspace`: 增加复盘入口与复盘面板的布局要求。

## Impact

- 数据：新增 `cycle_reviews` 表与一次迁移；`agent_conversations.active_skill` 的 CHECK 约束需要扩展取值（SQLite 需重建表或落一条迁移）。
- 后端：新增 `review` 模块（事实采集、问题模板、持久化）、`review` 技能提示、若干净命令；跨周期聚合查询。
- 前端：复盘入口（列头/周期结束提示）、复盘面板、汇总视图、Markdown 导出。
- 依赖关系：建立在 `rebuild-baseline` 之上（需要 `focused_time`、任务完成状态、层级链接、agent 会话与提议机制）。
- 不受影响：原有的四技能行为、计划数据结构、提议机制。
