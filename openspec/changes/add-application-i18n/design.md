## Context

见 proposal.md。React 当前无语言抽象，设置以 SQLite `app_settings` 为真相，主题有首帧缓存。Rust 错误已有稳定 code，规则问题和回执同时包含结构化类型与固定文案。日期身份使用本地 ISO 日期，不能和显示格式混用。

## Goals / Non-Goals

**Goals:** 建立一个语言偏好、一套资源与格式化入口；现有界面完整迁移；切换不重建业务状态；后续语言增加可通过资源和集中校验完成。

**Non-Goals:** 不翻译用户数据、历史 LLM 消息、技术日志或自定义 persona/SKILL；不引入云翻译、语言专用数据库、持久化翻译副本，不改变计划或确认规则。

## Decisions

1. 使用本地打包的 `i18next` + `react-i18next`，集中封装 `src/lib/i18n`。组件订阅语言变化，普通函数运行时翻译；禁止模块加载时计算文案。相比自制替换器，它提供成熟的复数、插值及 React 更新行为。
2. 资源使用 `en` / `zh-CN` 目录，按 `common` / `shell` / `planning` / `ai` / `errors` / `backend` / `backend-actions` 划分命名空间。键为语义标识，句子整体翻译，动态值使用插值；静态资源完整性测试检验键和参数，英文复数使用 `_one` / `_other`。
3. `app_settings.locale` 保存规范化值，专用 `set_locale` 校验仅接受 `en` / `zh-CN`。首次通过系统 locale 推导并持久化。前端 localStorage 仅缓存首帧，设置查询回读作为真相。保存成功立即更新 i18n 和 `html.lang`；失败不切换。Coach 设置工具同样经过确认和服务校验。
4. `Intl.DateTimeFormat` / `Intl.NumberFormat` 统一显示；日期字符串按本地年月日解析，不能通过 `new Date(YYYY-MM-DD)` 产生 UTC 偏移。格式化函数只用于显示，不传回业务身份。
5. 错误在展示时根据稳定 code 转成语言资源；未知错误附本地化说明和原始诊断。规则问题、提案与工具状态使用现有类型和参数映射；审批详情保存稳定 key 和参数，freshness 比较不包含翻译结果，不通过匹配中文句子决定逻辑。原生通知用后端集中语言资源，用户标题正文保持原样。
6. 内置 SKILL 和默认 persona 使用英语编写。AI 请求在每次生成时读取当前偏好，由 system prompt 附加默认回复语言且允许用户明确覆盖；技能文件保持工作流和用户可编辑属性，不包含固定界面语言。历史消息保持生成时语言，已有用户修改文件不覆盖。AI 问题报告缓存同时核对生成语言，语言不同标记待重新检查；切换本身不发起请求或翻译旧报告。
7. 当前平台本机 UI 提供的系统菜单/权限提示仍由操作系统语言控制，应用自定义窗口栏和通知遵循应用语言。技术标识 `Goal`、provider/model ID、协议字段不翻译。

## Risks / Trade-offs

- 中文更紧凑而英语较长 → 控件自适应宽度与换行，真实窗口复核两种语言；月视图卡片移除重复的顶部专注数量，底部使用时钟图标与完成比，完整文案进入 aria/tooltip；不缩小字体掩盖溢出。
- 遗留模块初始化文案或缓存结果不更新 → 语言切换测试覆盖已挂载 UI 和动态状态，模块常量只存翻译键。
- 错误仅按 code 粒度未含动态参数 → 保留技术诊断，同时优先提供可行动的本地化提示；不改数据库错误身份。
- 原生默认语言与 WebView 不一致 → Rust 持久设置为最终真相，前端首帧缓存随后协调。

## Migration Plan

无需数据表迁移；首次读取补齐语言设置。旧数据、凭据及 bundle ID 不变。新增依赖纳入第三方许可清单。先完成资源与入口，再逐组迁移界面，执行资源/组件/Rust/GUI 验收后更新版本说明并发布 `v0.1.1`。回退二进制不破坏既有计划，语言键可被旧版忽略。
