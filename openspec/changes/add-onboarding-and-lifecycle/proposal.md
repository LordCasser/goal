## Why

`onboarding-guidance` 与 `app-lifecycle` 的规范已写好但未实现。这两个能力不是锦上添花：

- **引导决定了新用户能否在第一次会话里走通主链路**。产品的核心价值是「长期目标 → 今天」的逐层收窄，如果用户打开后不知道从哪开始，这个价值就无法被体验到。规范把它设计成五步可自动判定的清单，正是为了让主链路在首次使用中就被走一遍。
- **退出/反馈/更新是产品与用户的长期关系**，且退出调查是唯一能拿到"为什么不用了"的通道。

两者都不依赖 AI，可以独立完成。

## What Changes

- **五步引导清单**：进度由实际数据推导（不是手动勾选），可跳过且跳过被持久化，引导遗留数据可清理
- **一次性提示卡**：按功能点显示解释卡，关闭状态持久化
- **退出调查**：条件判定 + 已展示时间戳（避免重复打扰）、继续/确认退出两条出路、结果可上报
- **反馈与联系作者**：带版本与匿名标识，失败不丢内容，支持复制支持 ID
- **自动更新**：检查 / 下载 / 安装，安装前校验来源，失败不阻断使用
- **专注块到期通知**：到达计划时长发送系统通知，权限被拒时静默跳过

## Capabilities

### New Capabilities

无。两个能力的规范已存在，本变更是实现。

## Impact

- 后端：新增 `getting_started_guide`（进度推导与核对）、`exit_poll`（条件、生命周期、菜单）、`feedback`（上报与上下文采集）、`updater`（检查/下载/安装）、通知发送
- 数据：无新表；设置中持久化引导状态、已关闭提示 id 列表、退出调查已展示时间戳
- 前端：引导清单与进度环、提示卡、退出调查面板、反馈入口、更新提示（前端为独立任务）
- 平台：需要通知权限、更新签名校验、系统版本读取
- 依赖：`rebuild-baseline`（周期/任务数据用于推导引导进度、设置存储）。与 AI 无关，可与 AI 相关变更并行
- 与 `add-reminders-notifications` 的边界：本变更实现"专注块到期通知"这一条；后者把它收敛进通用提醒调度。若后者先做，本变更只保留引导与退出流程部分（届时以 `add-reminders-notifications` 的规范为准）
