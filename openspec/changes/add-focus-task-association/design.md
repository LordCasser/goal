## Context

现有 `cycles` 使用 `session` 表示专注块，`parent_id` 指向日；结束时累加区块和周期祖先的 `focused_time`。任务图通过 `tasks.parent_id` 跨周期连接，编辑态由 `TaskNode` 投影。删除影响集中于 `service/deletion.rs`，日历合并在一个事务中先移动任务再移动区块。需求动机见 `proposal.md`。

## Goals / Non-Goals

**Goals:** 保留现有分层与计时事实源；让关联在创建、任务投影、递归删除和内容移动的所有现有入口保持一致。

**Non-Goals:** 不增加关联实体、任务计时器、持久化任务累计、任务行专注入口或常驻统计组件，不扩展关联编辑或跨日关联，不改造长期/每周任务的时间汇总。

## Decisions

1. 新增可空 `cycles.task_id REFERENCES tasks(id) ON DELETE CASCADE`，只允许 `session` 携带关联。创建服务校验同日、非空标题、正式任务以及提议锁。数据库校验引用和区块类型，不加跨表实时触发器：合并事务先移动任务后移动区块，中间态短暂不满足同日关系。
2. `AddSessionArgs.task_id` 与 `Cycle.task_id` 直接表达可选关联；`TaskNode.focused_time` 在编辑态读取时从关联区块汇总，不添加第二个写入计数。其他纯任务树构建默认零，编辑态覆盖为数据库聚合值。
3. 删除影响闭包先取完整任务后代，再并入其关联区块。确认令牌包含关联与区块生命周期；相同闭包驱动提醒清理、幸存周期扣减以及失效通知。提议 Keep 删除复用同一清理路径；创建提议不能被关联，因此撤销新建不会留下已关联区块。
4. 任务单独移动时，在同一事务中解除同日子树的区块关联；日历整体移动保持关联。日历合并/交换同时迁移日与周期祖先累计，避免任务投影与日累计分离。
5. 重复模板不增加任务字段，实例天然不关联；原模板来源区块不变。
6. 关联选择放在现有添加专注块表单，候选项仅为同日正式且非空的任务，默认选择不关联。后端继续返回 `TaskNode.focused_time` 的派生数据，前端不以此新增常驻任务时长展示。

## Risks / Trade-offs

- [日历合并中的短暂跨日状态] → 同日校验位于创建服务，合并是原子事务，测试确认最终关联有效。
- [直接删除提议绕过服务清理] → Keep 的内部删除使用相同影响和清理函数，返回完整失效集合。
- [已有日历累计不一致] → 当前改动只迁移本次涉及区块的累计，不批量重算历史；历史修复属于独立数据审计事项。

## Migration Plan

追加版本 12，旧区块的关联默认为空，创建按任务查询的索引。使用现有迁移事务和校验和流程，失败整次回滚。发布前以迁移后临时数据库运行关联、计时、删除与移动回归测试。
