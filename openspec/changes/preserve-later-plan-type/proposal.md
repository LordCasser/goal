## Why

Later 当前只记录“暂存”状态，移入时无法保留用户已经表达的长期、周或日计划意图；提升操作也默认要求选择长期周期，导致周/日想法需要额外创建和选择容器。需要把计划类型作为 Later 项的明确状态保存，并让提升操作按当前本地日期安全复用目标周期，减少重复点击、孤立周期和类型丢失。

## What Changes

- 为 `Task` 增加 `later_plan_type`，取值为 `month`、`week`、`day` 或 `null`；只有属于 Later 容器的任务允许非 `null`。
- 用户把长期、周、日计划中的任务移入 Later 时，保留来源周期类型；同一周期的子树一起保留该类型，移出 Later 后清空字段，再次移入按当前所属周期重新记录。
- Later 中直接新增的想法，以及缺少该元数据的旧 Later 数据，按长期（`month`）处理，不推断旧来源。
- 保留长期类型的现有提升流程；周默认提升到按 `week_start_day` 解析的本周，日默认提升到本地今天。无目标周/日时原子创建并移动，重复点击或失败不得留下空周期。
- 复用共享的任务移动事务 helper，保持原有任务关系与子树；当来源是已有同周期子任务且父项未随迁、跨同级周期移动会产生无效父关联时解除该父关联，合法相邻层父关联继续保留。
- Later 行展示静态小字类型提示，操作按钮明确为“安排到本周 / 今天 / 长期周期”；错误以内联方式显示，不增加成功 toast 或新的视觉层。
- 更新工作台规范和用户指南中的 Later 说明，补充类型保留、默认目标周期与失败行为。

## Capabilities

### New Capabilities

无。本变更扩展现有 Later、任务移动和计划周期能力。

### Modified Capabilities

- `planning-cycles`：Later 项需要保留计划类型，周/日提升目标由后端按当前本地日期与周起始设置解析并复用或原子创建。
- `task-graph`：任务移动需要维护 `later_plan_type`，并在跨周期移动时保持或解除无效的同周期父关联。
- `planner-workspace`：Later 行展示类型并提供按类型明确的提升入口、错误反馈和周/日默认行为。

## Impact

- SQLite `tasks` 及其约束、迁移、任务查询/序列化结构需要增加 `later_plan_type`；Later 读写、任务移动和 `promote_later_goal` 命令/API 需要统一事务语义。
- Rust 的周期日期解析、任务仓储/服务与共享 move helper 受影响；前端 IPC 类型、Later 面板、行操作和本地化文案需要同步。
- 需要覆盖已有 Later 数据、长期直接提升、周/日目标周期复用或创建、失败回滚、重复点击以及父子关系边界的后端和前端验收。
- 前置依赖为 `rebuild-baseline` 已建立的 Later、任务树、周期日期和 IPC 契约；本变更不引入独立 Later 实体，也不做关系历史恢复。
