## MODIFIED Requirements

### Requirement: 日历身份唯一

带日历含义的周期 SHALL 通过 `calendar_key` 唯一标识，系统 MUST NOT 允许同一个 `calendar_key` 存在两条周期。键 SHALL 是带类型前缀的复合串，且 MUST 与用户可见的周期日期身份一致。

| 类型 | 键 |
| --- | --- |
| `day` | `day:{本地日期}` |
| `week` | `week:{该周首日}` |
| 有结束日的 `month` | `long-term:{starts_on}:{ends_on}` |
| 无结束日的 `month` | `long-term:{starts_on}:open` |
| `session` / Do Later | 无键 |

周的键使用该周首日，因此会随用户设置的周起始日变化。日期边界由 `starts_on` / `ends_on` 表达；无结束日的长期周期只保留开始日。

#### Scenario: 重复创建同一天
- **WHEN** 对同一日期再次创建 day 周期
- **THEN** 唯一约束拒绝，调用方应改为复用已存在的周期

#### Scenario: 长周期的键体现起止
- **WHEN** 创建一个从某日开始的 3 个月长周期
- **THEN** 其 `calendar_key` 同时包含起始日与结束日，因此同一起始日的不同时长周期不会互相冲突

#### Scenario: 无期限长周期身份
- **WHEN** 从同一天创建两个无结束日的长期周期
- **THEN** 第二个周期因日期身份重复而被拒绝；同日起始但有结束日的长期周期仍可创建

#### Scenario: 周键随起始日设置变化
- **WHEN** 用户更改周起始日设置
- **THEN** 之后创建的周周期使用新的周首日生成键；既有周周期不受影响

#### Scenario: 首次确定周起始日
- **WHEN** 用户首次打开需要周起始日的界面
- **THEN** 系统按系统区域推断并持久化 `week_start_day`，之后不再变更

### Requirement: 长周期时长受限选项

Long-term cycle SHALL 支持 1 / 3 / 6 个产品月、自定义起止日和无固定结束日。预设时长 MUST 按 28 天为一个产品月计算；自定义周期的时长为起止日相差的整天数。无结束日的长期周期 MUST 有有效开始日，且不产生时长和结束日。

#### Scenario: 选择 3 个月
- **WHEN** 用户在周期选择界面选中 3 个月并确认
- **THEN** 系统创建 `type='month'` 周期，时长为 84 天，`starts_on` 为今天，`ends_on` 为 `starts_on` 加 84 天，列头显示的剩余周数为整数

#### Scenario: 三档时长均落在整周上
- **WHEN** 用户分别选择 1 / 3 / 6 个月
- **THEN** 对应时长分别为 28 / 84 / 168 天，全部是 7 的整数倍

#### Scenario: 自定义结束日
- **WHEN** 用户提供有效开始日和晚于开始日的结束日
- **THEN** 周期按这两个本地日期保存，时长等于相差的整天数

#### Scenario: 无固定结束日
- **WHEN** 用户选择无固定结束日并提供有效开始日
- **THEN** 周期保存该开始日，结束日和时长为空，不自动安排复盘日期

#### Scenario: 时长超出允许集合
- **WHEN** 调用方提交不在预设集合内的产品月时长
- **THEN** 系统拒绝并返回校验错误

### Requirement: 启动周期前必须有时长

除无固定结束日的长期周期外，系统 MUST NOT 允许启动未设定时长的周期。无固定结束日的长期周期 SHALL 能手动开始和完成；没有时长的专注块仍不能开始。

#### Scenario: 无时长时启动被拒
- **WHEN** 用户尝试启动未设定时长的专注块
- **THEN** 系统拒绝并返回明确错误

#### Scenario: 有时长时正常启动
- **WHEN** 用户启动一个已设定时长的周期
- **THEN** 写入 `started=1` 与 `started_at`

#### Scenario: 无期限长期周期正常启动
- **WHEN** 用户启动一个有开始日但无结束日的长期周期
- **THEN** 写入 `started=1` 与 `started_at`，且用户之后可手动完成

## ADDED Requirements

### Requirement: 长周期进度检查独立于结束日

系统 SHALL 允许长期周期不设进度检查、指定一次检查或定期检查，且该选择 MUST 与是否有结束日独立。指定一次的日期 MUST 不早于开始日；有结束日时 MUST 早于结束日。定期检查间隔 MUST 是正整数天；有结束日时只显示结束日前的检查，无结束日时持续推导未来检查。

#### Scenario: 有结束日但无检查
- **WHEN** 用户创建有结束日的长期周期并选择无进度检查
- **THEN** 周期保留结束日，不显示或投递进度检查

#### Scenario: 无结束日且无检查
- **WHEN** 用户创建无结束日的长期周期并选择无进度检查
- **THEN** 周期不产生检查安排，也不生成虚构的结束提醒

#### Scenario: 无结束日且定期检查
- **WHEN** 用户创建无结束日的长期周期并设定每 14 天检查
- **THEN** 系统从开始日持续推导每 14 天的检查，不要求结束日

#### Scenario: 无结束日且指定一次
- **WHEN** 用户创建无结束日的长期周期并指定开始日之后的一天检查
- **THEN** 系统保存该日期作为唯一检查日

#### Scenario: 检查日期或间隔无效
- **WHEN** 指定一次的检查日期早于开始日，或定期间隔不大于零
- **THEN** 系统拒绝创建并返回明确校验错误

### Requirement: 无期限长周期覆盖未来日期

无结束日且未完成的长期周期 SHALL 在开始日起持续覆盖之后的日历日期和工作台选择；完成后仍保留历史内容，不再被当作当前未完成周期。

#### Scenario: 查询未来日期
- **WHEN** 无结束日长期周期开始后查询晚于开始日的日期
- **THEN** 周期可被找到，关联的目标仍可展示

#### Scenario: 选择当前长期周期
- **WHEN** 工作台没有显式选中长期周期，且存在覆盖今天的未完成无期限周期
- **THEN** 工作台可默认选中该周期
