## Context

基线已有 `session_expiry_worker` 式的到期通知（见 `openspec/specs/app-lifecycle/spec.md` 的「专注块结束通知」）。本变更把它扩展成一套通用提醒，而不是再造一条平行的通知路径。

关键约束：这是一个**本地优先、不常驻**的桌面应用。用户关掉窗口后进程不保证存活。

## Goals / Non-Goals

**Goals:**

- 任务、日计划、周期尾声三类提醒，共用一套持久化与调度
- 权限被拒、免打扰、应用未运行三种情况都有明确且不丢信息的降级
- 与既有专注块到期通知收敛到同一实现

**Non-Goals:**

- 不做跨设备提醒（没有同步）
- 不做基于位置的提醒
- 不做重复提醒规则引擎（只支持单次触发 + 可选的每日重复）
- 不替换系统日历，不写系统提醒事项

## Decisions

### D1：只在应用运行时弹系统通知，错过的在启动时补偿

替代方案是注册系统级定时通知（macOS `UNUserNotificationCenter` 的日历触发器），进程不在也能弹出。这需要写原生桥接，且要处理权限、时区与撤销的完整语义，成本远高于本变更的收益。

选择：进程内调度 + 启动补偿。越过的提醒不会丢失，而是汇总成一次启动摘要，用户能看到「昨天有 2 条提醒你没看到」。

**能力上限**：应用完全退出期间不会有系统通知。
**重新评估的触发条件**：如果实际使用中出现「用户抱怨没收到提醒」或「错过提醒摘要里长期出现同一类条目」，说明进程内调度不够，再考虑原生调度。
**演进边界**：`reminders` 表已经按 `fire_at` 落库，将来换成原生调度只需要改变投递方式，不需要改数据模型。

### D2：提醒不携带业务逻辑，只做投递

提醒记录只知道「什么时候、指向哪个对象」。点击通知后的跳转由前端按 `target_kind` 解析。这样提醒模块不需要理解周期层级。

### D3：免打扰只抑制系统通知，不抑制记录

免打扰时段内的提醒仍然写入 `fired_at`，只是不弹窗，并在应用内以弱提示呈现。否则用户一旦开启免打扰就会永久丢失那段时间的提醒。

### D4：与专注块到期通知收敛

专注块到期通知改为由同一调度器投递，但保持其既有对外行为（到达计划时长即通知）。这样只有一处处理权限、免打扰与投递失败。

## Risks / Trade-offs

| 风险 | 影响 | 处理 |
| --- | --- | --- |
| 应用未运行导致提醒不弹 | 用户可能错过 | 启动补偿摘要；并在设置里如实说明这一点，不暗示它像系统日历一样可靠 |
| 启动时大量错过的提醒造成摘要轰炸 | 用户反感 | 摘要按类型聚合计数，最多展示 3 条明细，其余折叠 |
| 系统权限被拒绝后用户以为提醒坏了 | 信任受损 | 权限被拒时在设置页与提醒设置入口给出明确状态与恢复指引；应用内提示不中断 |
| 调度器随应用生命周期启停 | 长时休眠后定时器漂移 | 每次唤醒与窗口聚焦时对 `fire_at <= now` 重新对账，不依赖定时器精度 |
| 与专注块既有通知重复投递 | 用户收到两条 | 专注块到期只由调度器投递，原实现路径移除（对外行为不变） |
