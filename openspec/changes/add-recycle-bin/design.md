## Context

见 [proposal.md](proposal.md)。现有任务与周期删除通过 `service/deletion.rs` 计算包含跨周期子任务和关联专注块的影响闭包，随后清理提醒、调整存活周期的专注时间汇总，再利用外键级联从活动表移除。所有编辑器、日历、Later 和 Coach 均读取这些活动表；删除影响预览和确认令牌已存在。`docs/architecture.md` 要求数据库为唯一真相源，Tauri 事件只负责缓存失效。

## Goals / Non-Goals

**Goals:**

- 在一次事务内保存完整删除影响并移走活动数据；恢复与永久删除也各自原子提交。
- 保持活动查询和现有删除守卫的语义，让跨计划关联与专注汇总可精确恢复。
- 让用户在同一个左侧抽屉位置查看 Later 或回收站，明确区分可恢复删除与永久删除。

**Non-Goals:**

- 自动过期、自动清空和云端同步回收站。
- 修改现有周期删除守卫或允许恢复到替代位置。
- 将放弃的 Coach 提议、新建提议的撤销或普通数据维护清理写入回收站。

## Decisions

### 1. 每次删除保存一个独立快照

新增 `trash_entries`，保存条目身份、目标种类、原标题、来源、删除时间、影响计数及完整快照。快照只包含该次删除会移除的周期、任务、预览原值、计划问题忽略记录、复盘及其处置、提醒；保留原 ID、周期、父项、位置和时间字段。活动行仍由现有删除路径移除。这样无需给大量现有读查询增加「未删除」条件，也不会把已确认删除与 Coach 待确认提议混为一谈。

曾考虑给周期与任务添加软删除标记，但跨周期级联、提醒和复盘的所有查询都必须同时过滤，容易出现幽灵关系；按实体复制整套回收站表则造成持续的模式重复。单条快照按实际删除影响组织，边界最小。

快照只在事务内由当前数据库行生成，不接受前端提交的内容。未来若迁移修改已保存字段的含义或删除列，迁移须同时升级回收站快照；纯新增可空或带默认值列可由恢复插入的缺省值处理。

### 2. 删除与恢复复用现有影响规则

目标与周期的 GUI 删除仍先校验影响预览令牌和既有守卫。确认后在同一事务内计算影响、写快照、执行 `prepare_deletion` 和现有删除。单个专注块以及日计划的批量专注块删除也进入回收站；同一次批量动作须形成一个条目。已确认的 Coach 删除调用同一路径；待确认提议保持活动行及预览标记，Keep 时才产生回收站条目。

恢复事务把原行写回原 ID、父项、周期与位置，外键检查延迟至全部相关行插入后。存活周期曾在删除时扣减的专注时间在恢复时加回，快照内一同恢复的周期保留其原汇总，避免重复计算。日期身份、父项或其他约束冲突使整次恢复回滚，条目保持可重试。来源文本只用于展示，恢复依据原 ID 和关系，不根据名称猜测位置。

永久删除在回收站中接收选中的条目 ID，一次事务验证选择并移除快照；活动数据已在删除时移走。对不存在或已变化的选择返回明确错误，避免部分成功。

### 3. 命令、事件与界面

Tauri 提供列出、恢复和批量永久删除三个命令。删除、恢复和永久删除成功后发 `trash:changed` 空载荷失效通知；恢复及删除仍发既有 `cycles:changed`、`tasks:changed`，让工作台、日历和 Later 重新读取数据库。

工具栏在 Later 紧邻处增加回收站按钮，两个按钮控制同一左侧抽屉宽度。回收站行显示标题、来源与删除时间，长标题单行省略号，逐项恢复动作靠近对应行。列表提供全选和逐项选择，选择数量与危险动作清晰可见；彻底删除先弹二次确认，默认焦点落在取消。使用现有颜色、字号、描边和按钮组件，并支持键盘焦点与 Escape 退出。

## Risks / Trade-offs

- [跨表级联遗漏] → 以现有删除影响闭包为唯一枚举来源，测试覆盖跨计划子任务、复盘处置、提醒和专注块，删除前后核对实际行集合。
- [恢复时原计划不存在或日期被占用] → 整个事务回滚并保留条目，界面提示先恢复上级计划或解决冲突；不自动改变来源。
- [专注时间汇总重复或丢失] → 区分随快照恢复的周期与一直存活的祖先，分别保留原值或增量补回，集成测试覆盖多层汇总。
- [大计划快照增加本地磁盘用量] → 按需读取回收站元数据，快照仅在恢复时读取；永久删除立即释放快照，可在验收中测量大计划操作耗时和数据库大小。
- [后续模式迁移使旧快照不可恢复] → 数据迁移评审必须检查回收站载荷；改变已有列时同步转换保存的快照并用跨版本恢复测试验证。

## Migration Plan

追加迁移创建回收站条目表和删除时间索引，既有活动数据原样保留。部署前可使用现有本地数据库备份功能导出备份。按数据事务、命令和事件、界面顺序上线；迁移后以集成测试验证旧数据删除、恢复、永久删除与备份导出。若新版本出现恢复故障，先停止永久删除入口并修复新版本，再从备份或仍在回收站的快照恢复；不改写已应用的迁移。
