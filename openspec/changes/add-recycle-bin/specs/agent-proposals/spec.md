## MODIFIED Requirements

### Requirement: 提议态与已提交态严格分离

系统 MUST NOT 用同一个字段同时表达「已提交的删除」与「尚未处理的提议」。已确认的删除 SHALL 从活动任务中移除并形成回收站条目；待确认的改动 SHALL 只由提议状态表达。回收站中的已确认删除 MUST NOT 再表现为待确认提议。

#### Scenario: 未确认的删除
- **WHEN** agent 提议删除一个任务
- **THEN** 该任务仍出现在活动界面，标记为待删除，用户可以选择撤销；回收站不出现该提议

#### Scenario: 已确认的删除
- **WHEN** 用户确认 agent 提议的删除
- **THEN** 任务从活动界面移除，并在回收站中成为可恢复条目，不留下待确认标记

#### Scenario: 查询可见任务
- **WHEN** 列出某周期的活动任务
- **THEN** 待确认提议与已提交内容仍可区分；已进入回收站的任务不出现在活动列表

### Requirement: 主体预览与 Coach 单一确认入口

编辑投影 SHALL 直接显示待确认的标题、完成状态与内容，保留任务 ID、顺序和层级。受影响任务 SHALL 以轻量浅底和锁定标识区分；删除线只作用于待删除任务标题。主体 MUST NOT 出现 Keep / Revert 或第二套确认控件。Coach 关闭时，工具栏计数只负责重新打开 Coach。

#### Scenario: 尚未确认
- **WHEN** Coach 产生任务预览
- **THEN** Workspace 和 Calendar 同步呈现预览，不把它作为已提交的统计
- **AND** 受影响项禁止手动改名、勾选、删除、移动、归属、颜色与重排；后端服务同样拒绝这些写入
- **AND** 删除会级联影响的关联事务也显示待删除并锁定，Coach 列出影响范围
- **AND** 不受影响的任务仍可正常编辑

#### Scenario: 确认修改
- **WHEN** 用户在 Coach 点击确认
- **THEN** 当前预览成为正式结果，快照与预览标记清除，任务解锁；确认删除则移入回收站
- **AND** 对应原工具记录由“待确认”变为“已确认”，聊天新增具体完成消息

#### Scenario: 拒绝修改
- **WHEN** 用户在 Coach 拒绝
- **THEN** 原标题、完成态、子步骤、位置、关系、颜色和详细内容恢复，原本不存在的任务移除
- **AND** 主体去掉预览标记并解锁；原工具记录变为“已放弃”，聊天保存实际处理结果
