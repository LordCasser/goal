## Context

见 [proposal.md](proposal.md)。当前长期目标、周目标、日事项和同周期子步骤都保存在统一任务图中；`parent_id` 同时表示同周期树父节点或跨周期直接目标链接。专注块是独立周期，可选地关联日事项，不是事务身份。前端已有任务行首拖动把手、目标选择器、周期菜单、专注块时间编辑器和通用弹窗；把手只负责同一计划列表内排序，其余业务移动与关联使用菜单或表单。SQLite 是事实源；Tauri 事件仅通知缓存失效。

## Goals / Non-Goals

**Goals:**

- 用现有任务身份和链接关系推导事务，避免为同标题记录新建实体。
- 备注只归属于一条任务记录，跨日历史只读聚合，不偷偷同步内容。
- 仅保留同一计划列表内的任务行排序拖动把手；跨列表和其他业务操作都有明确、键盘可达的入口。
- 自动导入只绑定用户明确的新建计划动作，事务性写入且可重试。

**Non-Goals:**

- 不把专注时长、工作日或空白日期推断为实际投入时长；展示的“历时”是首末记录之间的自然日数。
- 不为事务提供手动合并、重命名或独立生命周期。
- 不改动窗口标题栏的系统拖动。

## Decisions

### 1. 备注是任务字段，详情是逐条入口

新增 `tasks.note TEXT NOT NULL DEFAULT ''`，贯穿 Rust `Task`、仓储投影与更新、IPC 类型。默认纯文本；避免富文本格式、编辑器状态和额外备注表。备注在任务详情弹窗内编辑；双击非空任务行（包括标题）打开详情，单击标题保持原有行内编辑。详情显示标题、所属日期／周期、直接上级目标和备注；日事项另展示按日期排列的同一事务段落。保存失败时弹窗保留草稿与错误，Escape 关闭前若有未保存修改则由弹窗既有关闭约定处理。已结束周期只读。手动复制和自动导入创建的新行均使用空备注；移动同一行时保留备注。AI 提议修改标题等字段时不覆盖备注，新增行的备注为空。

替代方案是给“事务”建立共享详情表；这会让各日期的进展相互覆盖，违背逐条备注的用途，因此不采用。

### 2. 同标题事务按当前图派生

仅考虑已确认、非空、顶层日任务。顶层定义为没有同日周期的任务父节点；跨周期 `parent_id` 仍是可见根。键为 `(title.trim(), direct_parent_goal_id | None)`，比较保留内部空白、大小写和标点，目标使用行 ID 而非目标文字或间接祖先。按日期聚合，同日同键的记录形成一个日期桶；日期桶中任一记录完成，即在该日结束当前段落。之后同键首次出现新记录时开启新段落。段落历时为首末记录日的闭区间天数，记录天数为不同日期桶数量；未完成段落截至末次记录日，不自动算到今天。日期运算放在 `domain/calendar.rs`，分段规则放在任务领域／服务，按需从详情入口读取，不新增持久化事务表。改标题、链接或完成状态后按当前图重算；备注本身不参与分组。

替代方案是用 `copied_from_task_id` 或专注块串联：前者漏掉手动新增的同名事项，后者强制用户使用专注块，均不符合要求。

### 3. 计划创建与导入在一个显式事务中

设置增加一个布尔值 `auto_carry_unfinished`，默认关闭，同时控制周与日。创建入口保持明确：`create_planning_cycle` 创建周、显式“创建日计划”命令创建日；内部 `get_or_create_day_in_tx` 仍只负责确保日期存在，因为 Later 安排和日历移动也调用它。导入来源是紧邻自然周／日的已保存周期，不沿用手动“从上一已保存周期复制”的寻找策略。仅复制已确认、非空且未完成的顶层事项及其未完成同周期步骤；目标侧以 `(trimmed_title, direct_parent_goal_id)` 防重，按来源顺序处理重复键，只导入第一条。保留来源血缘和适用的外部关联，备注置空。若周／日一起新建，两层导入共享同一数据库事务。对跨周的旧周目标链接，优先映射到本次导入的对应新周目标；无法映射时保留旧链接并在详情中显示实际归属，不伪装为本周目标。后续若产品不允许跨周旧目标关联，应另立变更处理既有手动复制语义。

替代方案是在通用“确保日期”函数中导入；这会让稍后事项安排、日历改期等隐式写入，故不采用。数据库已有周期日期唯一性与任务外键继续保证原子性，额外防重在服务中按键执行。

### 4. 稍后数量沿用现有查询

设置增加 `show_later_count`，默认开启。窗口栏使用与稍后面板一致的编辑工作区查询，递归树只计已确认、标题非空的可见顶层事项；已完成仍属于稍后，计入。数字 0 正常显示，超过 99 显示 99+，辅助标签读出准确数量。事件只使查询失效，不传计数。不增加计数表或单独缓存。

### 5. 任务行把手负责列表内排序，其余业务拖拽改用明确入口

非空且可编辑的任务保留行首小拖动把手，单项列表也保留；默认隐藏，悬停行或键盘聚焦时显示，沿用提示文字色与焦点显露状态，保留现有后端排序服务，仅允许在同一计划列表内调整任务顺序。不增加右侧独立排序按钮。跨计划列表或跨周期拖动不得移动任务、改动其顺序或目标关联。目标关联、日计划改期和专注块排期继续使用明确的菜单或表单入口：

| 操作 | 入口 |
| --- | --- |
| 同一计划列表内任务重排 | 行首小把手；按现有可见同级组更新位置 |
| 跨列表／跨周期移动任务 | 稍后或周期菜单，沿用目标容器校验 |
| 建立目标关联 | 现有色槽的上级目标选择器，右键菜单可打开同一入口 |
| 日历改期 | 日计划菜单“移到日期”，日期选择后沿用目标占用时的移动／合并／交换确认 |
| 专注块排期或移回待排区 | 现有时间编辑浮层填写开始时间或选择“移回未安排”；不保留时间轴拖动 |

不删除有其他调用者的领域服务。同步修订 `docs/design.md`、`docs/desktop-build.md`、主规范中的拖拽描述及仍活跃的 `add-calendar-time-view` 变更文档，避免同仓库相互矛盾。

### 6. 自有右键菜单是辅助入口

在 Web 内容根部拦截 `contextmenu`，根据最近的任务／周期／专注块上下文呈现菜单；点击外部、Escape、滚动或对象失效后关闭。菜单定位由触发坐标或键盘焦点锚点决定，并夹入视口。复用现有 `Popover` 的角色、焦点和样式语义，不复制一套菜单组件。文本输入区菜单提供剪切、复制、粘贴、全选并保存原选区；剪贴板读写使用可在 Tauri WebView 中工作的能力，失败要给出可理解的反馈。菜单命令调用与可见按钮相同的服务动作和失效路径。任务行首把手保留同一计划列表内的排序和键盘路径，目标色槽继续提供链接入口；不显示独立的右侧排序按钮。

替代方案是只有右键入口；这不利于触屏、键盘和功能发现，因此主要动作仍留在可见 UI。

## Risks / Trade-offs

- [历史链接或标题被修改后事务归组改变] → 明确标为“依据当前标题与关联”，不在没有版本历史的情况下伪造旧归属。
- [同一日期同键存在多条记录，缺少完成时间] → 以日期为最小粒度；该日任一完成即在日末结束，排序不声称有更细时间线。
- [新周复制的日事项仍指向旧周目标] → 显示真实目标；能映射到本次复制的新目标时映射，不隐式推断其他目标。
- [双击标题与双击选词冲突] → 双击明确打开详情，仍可用拖动选取文本和键盘选择文字。
- [右键剪贴板在各平台权限不同] → 在 macOS、Windows、Linux WebView 实机验收剪切／复制／粘贴，不以浏览器模拟测试代替。
- [跨列表拖动可能被误认为移动或改关联] → 仅在同一计划列表内接受排序拖动；其余列表和周期不作为拖放目标，菜单或表单处理归属与移动。
- [日历改期与专注块排期需要可发现的非拖拽路径] → 使用既有日期选择与时间编辑入口，并沿用冲突策略和排期服务。

## Migration Plan

1. 添加可空数据的默认备注列与两个默认值设置，旧数据读取为空备注、自动导入关闭、稍后计数开启。
2. 先落地领域读写与导入事务，确认旧计划内容不变。
3. 接入详情、归组与设置，将任务拖动限制为同一计划列表内排序，并更新其他业务操作入口和规范。
4. 在三平台验证上下文菜单、剪贴板、键盘焦点及窗口标题栏拖动；失败时回滚应用版本即可，新增列对旧数据无破坏性写入。
