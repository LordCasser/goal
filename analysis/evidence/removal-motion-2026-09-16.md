# 规划列表删除退场验收

范围：任务/目标、稍后任务、专注块，以及删除长期/周/日计划后的卡片切换。延续既有 UI 风格，不新增提示或业务状态。

## 实现与 review

- `RemovalList` 仅保留已从查询结果消失的展示节点，不延迟数据库写入、不恢复查询缓存。内容 160ms 原位淡出；占位在 80ms 后用 260ms 平缓收拢，总计 340ms。
- 退场节点 `inert`、`aria-hidden`；React capture 阻止残留点击、输入、blur 保存和 portal 动作。支持减少动态效果、卸载清理、快速独立删除和相同 ID 恢复。
- 同批递归删除按原顺序同时退场；修正 review 发现的倒序插入问题，并加入顺序断言。新增空白输入行留在退场任务之后。
- 工作构成消失同样收拢占位，空态在最后一个节点退场后出现。长期计划接入既有 `PlanTransition`，独立预取目标数据，不阻塞周/日导航。

## 验证

- 前端全量：62 文件、463 测试通过；包括 9 项 RemovalList 回归、29 项工作台回归。覆盖失败/取消删除既有语义、层级删除、恢复、portal 防护、减少动态效果及空态时序。
- TypeScript、Vite 和 macOS Tauri debug app 构建通过。OpenSpec 全部严格校验 30/30；`git diff --check` 通过。
- 真实浏览器运行实际 TaskList、删除 hook 和 query invalidation，IPC 使用仅内存 fixture：删除请求成功后才开始退场；逐帧采样 79 帧，其中 42 帧退场，占位从 36px 连续收拢至 0px，相邻行 top 从 174px 连续移动到 138px，均无反向跳变。
- 模拟后端失败：错误提示出现，原条目仍在、无退场节点。批量清空 8 行及摘要时同时出现 9 个退场节点，完成后全部清理。专注块连续删除后显示空态；浏览器无 error/warn。
- 使用固定签名身份生成 `.artifacts/desktop/smooth-removal/Goal.app`，原生启动后工作台/卡片/专注块正常。未在用户真实数据上执行删除；动效数据删除验证使用可重新加载恢复的内存 fixture。
- 临时 fixture、Vite 服务、旧桌面验收包与可再生 Rust 构建缓存已清理。Windows 物理鼠标实机验收仍留在任务 2.4，未据此声称跨平台实机验证完成。
