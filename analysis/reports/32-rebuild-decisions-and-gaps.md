# 重做前的产品决策、证据缺口与规范债务

本轮只形成需求候选和复测事实，不修改应用实现、数据库模型或既有 OpenSpec 变更。以下问题拆开处理，避免把“补 UX 需求”扩成整仓重构。

[核心需求](30-core-ux-requirements.md) 的 `UXR-xxx` 是可修改基线；[实际使用记录](31-product-use-and-evidence.md) 是来源。下面的建议不等于你已经决定，后续新增想法可以直接替换建议。

## 0x00 需要你后续选择的产品规则

### Q01 工作台保留什么空间关系

- **事实**：O09 中 Focus Blocks 跟随所选日，长期/周/日有各自时间导航，执行区没有第四套日期导航。窄视口无法完整同时显示全部内容。
- **旧材料差异**：旧 UX 总结写成“四个层级同屏并排”；`planner-workspace` 的 Purpose 也容易被读成四个独立周期栏目。
- **建议**：保留连续时间尺度，定义日工作区包括行动计划和执行块；允许横向浏览。不要把固定四列宽度或永远全可见当产品本质。
- **关联**：UXR-001/002/005；`planner-workspace`。

### Q02 移动、收纳、撤销怎样处理关系

- **事实**：O22 里移动后下游视觉链接消失，但原父引用仍保留。静态撤销记录源/目标周期，不能据此证明所有关系恢复。本轮 Undo 点击前已过期。
- **待选**：保留关联意图并在兼容时恢复；或显式解除并告知用户；或移动前给出影响提示。不能一边说已解除，一边保留可重新生效的隐藏引用。
- **建议**：保留内容与关联意图，对当前无效关系明确解释；及时撤销应恢复完整用户可见状态。若选择清空，撤销范围要包含关联。
- **关联**：UXR-011/013；`task-graph`、`planning-cycles`。

### Q03 未完成项接续如何避免重复

- **事实**：O18 验证复制保留来源与父链接；尚未验证重复点击、部分已完成子任务、跨长期周期接续。
- **待选**：默认只复制尚未接续的项，还是允许重复但明确告知；哪些步骤随副本保留。
- **建议**：默认防止同来源重复接续，并在动作前说明数量。保留历史原件，避免“复制”实际上改写过去。
- **关联**：UXR-004/006；`planning-cycles`、`task-graph`。

### Q04 日任务怎样进入专注块

- **事实**：同日有任务列表和执行块；本轮只手动在块中写行动，未拖动日任务进去。数据库中两者可以有独立任务内容。
- **待选**：复制一份执行清单；移动原任务；或引用同一行动并同步完成态。三者的完成、编辑、删除后果不同。
- **建议**：先确定用户期待的完成语义，再决定对象关系；不要因为发现复制元数据就推成全局共享任务，也不要提前新增执行任务实体。
- **关联**：UXR-007/011/016/018；`task-graph`、`planning-cycles`。

### Q05 目标色标与无色关系

- **事实**：当前目标有蓝色小标记；静态连线生成跳过缺少链接色的关系。标记是窄小色槽，不是必须使用彩色圆点。
- **旧材料差异**：`planner-workspace` 要求未着色目标使用中性连线，缺少对应实测支持；旧 UX 总结把颜色自动分配推广到每条目标。
- **官网复核补充**：W02 的 SVG 线与方形端点同色，深色描边属于行前色槽；既有规范把二者混为“端点更深”。官网同一示例目标在不同配图中色相不同，不能据此固定目标与具体颜色的对应。
- **建议**：默认给正式长期目标稳定信号，但不强迫收纳和未链接事项选色。若保留无色长期目标，明确其关系查看方式，并补无色场景。
- **关联**：UXR-009/010；`task-graph`、`planner-workspace`。

### Q06 引导记录体验还是当前有效数据

- **事实**：O23 恢复原数据库后仍 3/5，配置有完成步骤集合。此观察不是产品内删除测试。
- **旧材料差异**：`onboarding-guidance` 要求数据删除后对应步骤退回；又写引导示例数据清理，与旧报告的“不预置数据”混杂。
- **建议**：引导记录用户已经体验过什么，完成后不反复考核；当前计划健康另由反馈表达。教学卡与用户输入分开，不预置难清理的目标。若要选择实时退回，应明确这是主动改变。
- **关联**：UXR-014/015；`onboarding-guidance`。

### Q07 重复日程的未来范围

- **事实**：菜单有 Repeat daily，静态路径含停止重复和更新日程。未验证新日生成、未来已创建实例更新、实例单独修改。
- **旧材料差异**：`session-repeats` 同时出现“已存在实例保持原时长”与“修改影响尚未发生实例”，两者需要区分过去、未启动与未创建。
- **建议**：保护已发生执行；给修改明确范围，日程只复用标题、时长和顺序。通过实例脱离规则处理某日例外。
- **关联**：UXR-020；`session-repeats`。

### Q08 AI 确认覆盖哪些写入，批量范围是什么

- **事实**：任务有预览和原值快照；周期优先级结果等另有保存位置，不能仅凭任务快照证明“任何 AI 写入都受同样确认”。批量预览命令无周期参数，汇总包含受影响周期。
- **旧材料差异**：旧报告和项目配置泛称“AI 的任何写入”；`agent-proposals` 批量场景限定当前周期。
- **建议**：先明确任务、澄清信息、优先级结论、链接/复制动作各自确认契约。所有用户可感知计划变化都应有控制路径，批量操作先说明范围。具体机制随后设计。
- **关联**：UXR-024/025；`agent-proposals`、`agent-conversation`、`goal-clarification`、`prioritization`。

### Q09 周期、剩余时间与历史边界

- **事实**：三个时长预览是 28/84/168 天；下一长期周期接续既有结束日，不能一律从今天开始。未来周显示开始日期；菜单只看到 Delete，包含已启动执行的日不能删。
- **未坐实**：过去周期可删窗口 N、自动结束时刻、跨午夜与睡眠后的计时、时区与周起始日变化、所有类型统一手动结束入口。
- **建议**：保留明确日期与历史保护。周期时长是否固定是产品选择，不能仅凭菜单没有编辑入口证明作者要约束承诺，也不能写“结束当前周期”却没有可达入口。
- **关联**：UXR-002/003/019；`planning-cycles`、`app-lifecycle`。

### Q10 AI 失败与重新尝试

- **事实**：O17 的托管服务返回地区不支持错误，界面显示原始 JSON 和 Retry；O18 手动复制继续成功。
- **建议**：区分可重试网络错误与需配置/渠道改变的错误；保留输入和会话，提供可读操作说明。不要让 Retry 对永久条件形成无结果循环。
- **待复测**：成功工具回合、Keep/Revert、流式状态、恢复历史会话、取消与重复提交。本轮不能把历史成功消息当作当前服务可用证明。
- **官网复核补充**：W07 的免费规划、限时附带 AI、自带供应商及数据处理说明是参照产品当前声明。自有供应商、试用天数和商业模式仍可选择；W02 的预设成功对话不能替代实测。进入 AI 前的告知补入 UXR-035。
- **关联**：UXR-021～026/035；`ai-access`、`agent-conversation`。

### Q11 反馈、问题类型与调查不要混用

- **事实**：O06 已验证“没有长期链接”的具体计划问题；模型调用失败时结构性计数仍存在。问题忽略结构有周期/任务作用域。迁移史能证明评分结构被删除，不能证明用户研究结论。
- **旧材料差异**：`planning-issues` 写“AI 不可用则跳过审查”过于笼统；问题类型清单混入“不知道如何使用”“规划太费力”等产品调查信号，完整领域问题集合未由实测坐实。
- **建议**：结构性检查独立于 AI；语义检查单独降级。计划反馈给动作，不给人格或自律评分；调查走独立支持入口。完整类型、阈值和忽略失效规则单独核对。
- **关联**：UXR-027～030；`planning-issues`、`app-lifecycle`、`telemetry`。

### Q12 主动作的可达性、可读性与点击关系

- **事实**：可用 Enter 选择上层目标，存在快捷回复、焦点与减少动效样式；部分图标按钮在 AX 中无名称。hover 控件和轻色标不证明全部键盘路径可用。
- **建议**：为隐藏控件、拖拽和关系查看提供键盘路径；处理中文组合输入；小色标有文字确认路径。把低对比度当作需修正的实现取舍，不写成产品 MUST 低对比度。
- **用户已确认**：2026-09-14 增加点击目标或任务展示关联的需求，记录为 UXR-033。它是自有扩展，不能记为原产品已有点击锁定行为。
- **本轮交互建议**：点击后持续查看直接上下层关系，选另一项切换；标题编辑仍可用，完成框、菜单、拖拽维持原义；临时 hover 不覆盖点击选中。退出只清界面状态。键盘、Escape、切周期规则见 [官网复核](33-website-ux-ui-review.md)。默认不新增关系视图实体或跨启动持久化。
- **UI 差异**：官网 ≤1024px 用截图替换桌面演示，不证明应用小屏交互可用；官网与应用同名间距类取值不同。具体尺寸、圆角、阴影、颜色数量不作为硬性功能约束。
- **待复测**：纯键盘闭环、输入法、长列表、列内外滚动、色觉差异、减少动效。具体圆角、发丝线和字体不应成为不可改变的功能需求。
- **关联**：UXR-010/031/032/033；`planner-workspace`、`task-graph`。

## 0x01 独立记录的架构债务

这些事项影响未来实现，但本轮只记录，禁止顺手修改 schema、源码或变更任务。

| 编号 | 证据与问题 | 后续最小处理范围 |
| --- | --- | --- |
| A01 跨周期任务链接删除语义 | 原 schema 的 `tasks_table.parent_id` 是普通文本；同周期步骤另存 `subtasks`。自有架构将 `tasks.parent_id` 设为级联外键，而工作台规范又说删除上层目标保留下层项，行为冲突 | 先选择删除上层目标的用户行为，再对齐 `task-graph`、`planner-workspace`、架构及约束；不复制原字段形状作为理由 |
| A02 编辑、手动操作与 AI 重叠 | `agent-proposals` 因单用户禁止所有修订并发控制；同应用存在异步 AI 与手动编辑，单用户不等于没有重叠操作；会话本身已有 revision | 先定义进行中编辑、确认/撤销的冲突行为，采用满足该行为的最小协调方式；不先引入多用户版本体系 |
| A03 从未找到到断言不存在 | 技术报告把“未找到应用专属重试/超时常量”强化为“完全没有”；前端报告从 vendor 样式与 tippy 默认配置推断实际使用原生 popover 和作者动机 | 对影响 UX 的具体路径分别验证；保留“未证实”，不能据此为重做制定架构禁令 |
| A04 规范夹带原实现 | 周期、任务、会话规范夹带表名、字段和 IPC，容易把原实现历史当作新实现需求，且与项目“只写可观察行为”规则不一致 | 在产品规则确定后逐能力整理行为验收，架构归架构；不在本轮一口气重写 15 份规范 |

## 0x02 建议的后续复测包

| 包 | 前置条件 | 要验证的闭环 | 结果回填 |
| --- | --- | --- | --- |
| V01 AI 成功与确认 | 当前地区可用的托管渠道，或用户已有可用供应商 | 澄清 → 真提议 → 单条保留/撤销 → 跨周期批量 → 关闭重开；记录范围和原值恢复 | Q08/Q10、UXR-021～027 |
| V02 关系与执行 | 独立可恢复测试工作台 | 原产品：同周期步骤 → 跨层链接 → 收纳/撤销 → 跨列拖拽 → 日任务进入块 → 完成反馈；自有实现：点击持续查看、切换、退出与编辑兼容 | Q02/Q04/Q05/Q12、A01、UXR-033 |
| V03 时间与重复 | 可控测试日期和不影响真实记录的环境 | 下一周期 → 重复生成 → 某日修改 → 更新未来 → 停止重复；跨午夜、睡眠、重启 | Q03/Q07/Q09 |
| V04 新手与可达性 | 全新数据目录，中文输入法与纯键盘操作 | 无预置目标首启 → 五步 → 跳过 → 重开；隐藏控件、关系查看、长列表 | Q06/Q12 |
| V05 配套能力 | 用户后续明确需要该能力 | 录音与转写错误、通知、退出/反馈、更新、数据导出恢复 | 配套规范 |

V01 的前置条件是服务可用，不是要求用户在这轮提供凭据。V05 涉及权限和外部发送时按实际需要处理。本轮没有执行这些外部动作。

## 0x03 将来同步规范的范围

1. 先在 UXR 与 Q 表决定想保留/改变的行为，特别是链接删除、日任务与执行块、AI 批量范围。
2. 将已选行为写入对应能力的正常与边界场景，删除矛盾场景，保留证据来源。
3. 再更新自有架构与实施任务，架构债务按 A 表分别拆开。
4. 复盘、日历、提醒、本地模型继续作为自有扩展需求，不倒灌成原产品已验证特性。
