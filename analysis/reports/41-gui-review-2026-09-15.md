# Planner GUI 复核与第一轮调整

这轮检查的是已经实现的 Planner。对照对象是本地 Hyperfocus 0.15.0、`design.md` 和现有 OpenSpec。目标是保留长期目标 → 周计划 → 日计划 → 专注执行的流程，并把真实桌面界面调整到可以继续评审的状态。

当前结论：界面已经做了一轮调整，真实 App 里也发现并修复了任务编辑区无法加载的 IPC 问题。但**不能认定核心 UX 已完整复刻**。本轮已补上关系查看与归属操作；专注块行动清单以及部分配套功能入口仍有缺口，见后面的独立待办。

## 对照到的设计

原 App 的主工作台使用「时间导航 + 一个当前计划面」反复展开。导航表达周期，正文表达任务；这两层不能合并成“数据库里每个周期都变成一个内容列”。日计划后接专注块，任务输入始终是主要操作。

原 App 的设置从应用菜单进入，提供明确的返回计划入口。它本身只有较少的 AI 接入选项。我们的 BYOK 多供应商与模型配置更复杂，需要更宽的编辑区域，不能把它直接塞进原始大小的弹窗。

证据来源：

- 2026-09-15 通过原生 GUI 打开 `/Applications/hyperfocus.app`，查看长期/周/日工作台、应用菜单与设置。
- 之前的实际使用证据：`analysis/evidence/ux-audit-2026-09-14/`。
- 官网仅参考 App 展示，沿用 `analysis/reports/33-website-ux-ui-review.md` 的 W02–W06，不采用官网营销页面设计。
- 修改前截图：`analysis/evidence/gui-review-2026-09-15/before-workspace.png`、`before-settings.png`。

## 真实 GUI 发现的调用问题

创建长期、周、日周期可以成功，但编辑区最后显示 `Something went wrong`，没有输入行。原因不是空状态样式，而是顶层参数编码错误：

```text
旧调用：get_editor_workspace({ cycle_id: "…" })
实际要求：get_editor_workspace({ cycleId: "…" })
```

Tauri 默认命令参数使用 `camelCase`；`args`、`patch`、`config` 内的 serde 数据仍用 `snake_case`。[Tauri 官方调用文档](https://v2.tauri.app/develop/calling-rust/)明确区分这两层。原来的 IPC 测试把 Rust 参数拼写直接当成 JSON 键，因而 mock 测试能通过，真实 App 却失败。

修复覆盖当前五处 IPC 入口：`src/lib/ipc.ts`、calendar、onboarding、reminders、review 的 `api.ts`。只调整顶层键，没有改命令名、嵌套业务载荷或后端领域逻辑。相关 mock 断言同步改为实际协议。修复后在真实 Planner 窗口重新观察到长期、周、日的任务输入行。

窗口栏也使用了 [Tauri 官方配置](https://v2.tauri.app/reference/config/#titlebarstyle)所定义的 Overlay 语义，而不是仅改变网页背景色。

## 第二轮：任务行与关系交互

用户确认整体风格后，本轮只修正任务行对齐、按钮组语义、归属操作和过渡。任务正文统一使用 28px 第一行内容框：完成框、色槽和文字围绕同一行对齐，空行/三种周期保留一致色槽宽度。移除标题前的两枚红点，两个清晰度字段仍保留，合并为行尾可进入当前周期 Issues 的旗标。

Workspace / Calendar 置于互斥页面容器，Coach / Issues 位于分隔线另一侧并使用展开状态。后者和 Later 开关有 200ms 过渡，关闭过程立即 inert，过渡后卸载；页面、周期与关系用 180ms 淡入，菜单挂到 body 避免被计划列裁切。全部沿用系统减少动态效果约束。

关系编辑复用 `set_task_parent_link`、`root_color_key` 与现有查询，没有新建关系表。每个色槽有可点击区域，周目标选长期目标，日任务选周目标；仅列当前分支的兼容候选。点击正文只增加界面查看状态；点击完成、旗标、拖动、菜单不重选关系。未着色关系使用中性色和名称。解除关系保留任务与本周期步骤，失败保留原关系和选择器。

键盘补上两个实际边界：按 Escape 丢弃草稿时阻止 blur 再保存该草稿；已链接目标按 Enter 创建空行时不把跨周期 `parent_id` 传给只支持本周期子步骤的创建接口。Tab 可将已有跨周期归属的顶层行缩进为同周期步骤，跨周期归属本身仍不造成缩进。

第二轮自动化：34 个文件、189 项通过，TypeScript / Vite 构建通过。新增覆盖相邻层/分支边界、颜色继承及换绑、直接关系与步骤高亮、异常父链保护、选择/解除/失败/只读归属，以及 Escape/关联目标 Enter。仍使用 Node 26 的 `--no-experimental-webstorage` 测试参数；后续 BYOK 实测仅在 AI 上下文渲染处增加空输入行过滤，相关 5 项 Rust 测试通过。

真实 GUI 已由主 agent 完成长期/周目标改名、颜色保存和周→长期关联，蓝色继承及持久关系线可见。Luna 并行完成原版逐项对照和新版回归，两份独立结果见 [原版参考](42-hyperfocus-interaction-reference-2026-09-15.md)、[新版验收](43-planner-gui-verification-2026-09-15.md)。记录区分本次实测、历史证据与未执行操作。

GUI 回归另发现面板打开后 Escape 无效：焦点停在工具栏，但键盘处理仅在面板内部。已让 Coach / Issues 在打开时接收焦点，关闭后归还触发点，Escape 不再冒泡清掉关系查看；增加焦点和 IME 回归测试。

### BYOK 与额外 GUI 结果

用户提供的 DeepSeek BYOK 已在独立审计 App 中真实验证：连接成功、文本回复成功、`start_planning` 技能调用成功。配置使用 Anthropic Messages、`https://api.deepseek.com/anthropic` 与 `deepseek-flash`；上下文填写 1,000,000，本轮最大输出限制为 4,096。[DeepSeek 官方配置说明](https://api-docs.deepseek.com/quick_start/agent_integrations/claude_code/)确认地址与模型名，[模型文档](https://api-docs.deepseek.com/quick_start/pricing/)给出 1M 上下文。4,096 是本次测试选择，不是服务商的模型上限。

GUI 测试发现并修复关闭按钮内边距把 SVG 挤小的问题，`Button` 新增 icon 尺寸；模型文本使用 Markdown 排版，阻止原始 HTML 和远程图片自动加载。任务末尾输入占位行从模型上下文排除，防止 AI 把它统计为真实任务并追问。原始编辑数据不变。

最终包中已重新观察任务行、长期→周→日关系、定位及 Coach Markdown 排版。空行过滤的 5 项 Rust 上下文测试通过，新会话的模型计数也已实测通过：DeepSeek 回复当前周期只有 1 条任务 `Validate the first prototype`，没有把末尾空输入行计入。该请求曾因重新打包后的钥匙串读取确认而等待；用户完成系统弹窗后，请求正常结束。Coach 中回复可见，输入框恢复可用，会话 revision 为 1、没有 active turn 或 last_error。截图为 `after-byok-real-task-count.jpg`。

Coach 的历史工具事件仍用“正在…”描述，钥匙串等待也被泛化为“正在思考…”。这两个状态表达问题连同回合取消和面板重开恢复，记录为独立会话 UX 待办，避免在关系功能中扩大后端回合改动。

独立记录的剩余项：WebView 控制台观察到通知插件 `is_permission_granted` 缺少 capability，同时有 IPC 自定义协议 CSP 回退警告；当前已验证的任务、设置、BYOK 均可通过 postMessage 工作。通知权限与启动错误处理另列验证，不在关系与样式改动中扩大权限。
